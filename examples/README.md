# Examples

Open this folder in VS Code with the pliron extension. To try the extension
from source without installing it, run the following from the repository
root:

```sh
code --extensionDevelopmentPath="$PWD/editors/vscode" examples
```

Trust the folder when VS Code asks; dialect engines are only built in
trusted workspaces.

## `llvm/demo.pliron`: builtin + llvm dialects

This file is served by the reference engine bundled with the extension.

- **Colours.**
  - Op names show the dialect prefix and the op name in different colours.
  - Types, attribute keys, values (definitions and uses) and `^blocks` are
    coloured too.
  - `if` / `else` in `llvm.cond_br` and `variadic` in the function type are
    keywords. The real (hand-written) parsers report them as keywords; no
    grammar file contains them.
- **Go to source.** Cmd-click:
  - `llvm.add` opens the Rust definition in pliron-llvm. It is generated by
    a `macro_rules!` macro.
  - `builtin.constant` opens pliron's builtin dialect.
  - `z`, `^bb2` and `@callee` jump to their definitions.
- **Hover** shows exact types, op signatures, attributes and the Rust docs.
- **Inlay hints.** `r = llvm.call ...` shows `: builtin.integer i64`, a type
  the text does not spell out.
- **Errors.** Change `llvm.add` to `llvm.ad`, or use an undefined value. The
  real parser reports both, and keeps parsing after the first error.

## `toy/`: a custom dialect, picked up with no setup

`toy/toy-dialect` is a small dialect crate.

1. Open `toy/sample.pliron`. The first time, the status bar shows
   `pliron: building engine` for about 30-60 s while pliron and the dialect
   compile; later builds are incremental.
2. Then the custom ops get the same colours, hovers and Cmd-click
   navigation as the builtin ones. For example, Cmd-click `toy.add` to open
   `toy-dialect/src/lib.rs`.
3. Hot reload:
   1. In `toy-dialect/src/lib.rs`, change the format of `toy.print` from
      ``"`value` ` = ` $0"`` to ``"`show` $0"`` and save.
   2. After the rebuild, `toy.print value = c` is reported as an error.
   3. `toy.print show c` is accepted, and `show` is highlighted as a
      keyword.

From the command palette (or by clicking the status bar item), try
**pliron: View Engine Model**, **View Syntax Tree**, **Show Dialect
Registry** and **Show Status**.
